# Data

This directory holds the event logs, goal models, and generated pipeline output that GoalCat
operates on (the prompt templates live in `src/goalcat/templates/`). The pipeline itself and how to
run it are described in the [root README](../README.md). This document covers the study cases and
how to read an output run directory.

## Study cases

Each study case pairs a public event log (`logs/`) with a goal model (`goals/`): a GRL/URN
declaration of what the process is for, authored from the organization's published process
documentation and frozen before any categorization runs against it. Each goal model exists in two
forms:

- `<log>_goal_model.jucm` — the editable jUCMNav file and the only pipeline input. It is never sent
  to an LLM verbatim; Step 5a receives a task-scoped text projection of it (see "What the LLM
  actually sees of the goal model" in the [root README](../README.md)).
- `<log>GM_description.md` — documentation of how the `.jucm` was authored, for human readers
  only. No code parses it.

`goals/perturbed/` holds the Experiment 2 variants of the RTFM and Sepsis goal models, each with a
`.provenance.json`, generated by `experimentation/icpm2027/goalmodel/perturb.py`.

| Log | Domain | Scale | Files | Committed runs |
|---|---|---|---|---|
| RTFM (Road Traffic Fine Management Process) | Lifecycle of a road traffic fine, from issuance to closure, at an Italian local police force (*Polizia Locale*) | 150,370 cases, 561,470 events, 231 variants (Jan. 2000 – Jun. 2013) | `logs/rtfm.xes.gz`, `goals/rtfm_goal_model.jucm`; the 6-case fixture `logs/rtfm_mini.xes.gz` has its own structurally identical `goals/rtfm_mini_goal_model.jucm` | Accepted example runs for both logs (`output/rtfm_mini/` includes a Step 9 merge round). ICPM 2027 Experiments 1 and 2 on the full log. |
| BPIC 2019 | Purchase-order handling across 60 subsidiaries of a multinational coatings-and-paints company | 251,734 cases, 1,595,923 events, 42 activities, 11,973 variants | `logs/bpic2019.xes.gz`, `goals/bpic2019_goal_model.jucm` | ICPM 2027 Experiment 1 (guided, open, `guided_no_sample`, and label-list arms) and the Task C1 held-out label recovery against `case:Item Category`. No Experiment 2 perturbations. Its example run stopped after Step 6. |
| Sepsis | Hospital pathway of sepsis patients, recorded by the institution's ERP system | ~1,000 cases, ~15,000 events, 16 activities, 846 variants | `logs/sepsis.xes.gz`, `goals/sepsis_goal_model.jucm` | An accepted example run. ICPM 2027 Experiments 1 and 2 on both declared axes (admission, discharge). |

An earlier report of Step 5a instability on Sepsis **did not reproduce**: after a prompt defect was
fixed, the Task C12 rerun (k=5) produced one anchor set per axis
(`output/icpm2027_results/sepsis/stability_axis*.json`). The open reproducibility question is
Step 6 assignment variance, which the replicate ranges report. Run-level detail for every ICPM 2027
directory is in [`experimentation/icpm2027/RUNS.md`](../experimentation/icpm2027/RUNS.md).

## Reading an output run directory

Every execution writes to `data/output/<log_stem>/<run_id>/`, where `<log_stem>` is the log's
filename stem and `<run_id>` a `YYYYMMDD_HHMMSS` timestamp taken at start (e.g.
`data/output/rtfm_mini/20260917_192308/`, a run revised once and accepted on round 2). ICPM 2027
runs use `icpm2027_<condition_id>` instead; see
[`experimentation/icpm2027/RUNS.md`](../experimentation/icpm2027/RUNS.md).

```
<log_stem>/<run_id>/
├── run_config_snapshot.json    # the resolved PipelineConfig of this run
├── pipeline.log                # log of every step, all rounds
├── review_index.md             # index of the Step 9 review reports, all rounds
├── 01_variants/variants.csv
├── 02_profiling/               # profiles.csv, profiles.json
├── 03_textualization/          # lupin_input.json → LUPIN subprocess → lupin_output.json; narratives.csv
├── 04_sampling/narrative_sample.csv
├── round1/                     # Steps 5–9 of review round 1
│   ├── 05_taxonomy/            # taxonomy.json, taxonomy_prompt.txt, taxonomy_run_metadata.json
│   ├── 06_assignment/          # assignments.csv, assignment_report.md, assignment_prompts/,
│   │                           #   assignment_run_metadata.json, {structural,profile}_distances.parquet
│   ├── 07_discovery/           # discovery_metrics.csv, discovery_report.md, models/ (.png, .pnml)
│   ├── 07b_indicators/         # indicator_satisfaction.csv, goal_satisfaction.csv,
│   │                           #   indicator_report.md, <goal_model>_measured.jucm
│   ├── 08_description/         # descriptions.csv, description_report.md, description_prompt.txt,
│   │                           #   description_run_metadata.json
│   ├── 09_review/              # review_decisions.yaml, round_info.json
│   └── round_usage_summary.json
├── round2/                     # only if round 1 was revised with a merge or split
└── final/                      # only once a round is accepted
    ├── README.md               # generated summary of this run's accepted categories
    ├── taxonomy.json
    ├── assignments.csv
    ├── pipeline_usage_summary.json
    └── sublogs/                # <category_id>.xes.gz per category, plus residual.xes.gz
```

Notes:

- **Steps 1–4 run once per run directory.** They do not depend on the taxonomy, so a revision never
  re-executes them.
- **A new `round<N>/` appears only after a merge or split.** A rename is applied in place, with no
  LLM call; a run accepted on its first pass has only `round1/` and `final/`. A processed decision
  file is archived in `09_review/` as `review_decisions_processed_<timestamp>.yaml`.
- **`final/` exists only for an accepted run.** A run in progress or abandoned mid-review has only
  its step and round directories. `final/README.md` is generated per run; it reports on that
  execution and is not project documentation.
- **At acceptance** the accepted round's `taxonomy.json` is *moved* to `final/` (so that round's
  `05_taxonomy/` no longer holds it), `assignments.csv` is *copied* there (the round's copy stays
  canonical; the duplicate gives downstream tools a self-contained pair), and the round's
  `07_discovery/models/` is deleted, since the models are regenerable from those two files.
  Superseded rounds keep theirs.
- **`07b_indicators/`** is absent, not empty, when Step 7b did not run for a round
  (`skip_indicators: true`, no goal model, or no indicator bound to the log; all four goal models in
  `goals/` bind theirs).
- **Skipped computations leave schema-valid files.** With `skip_pairwise_distances`, both distance
  files are written with zero rows; with `skip_precision`, `discovery_metrics.csv`'s `precision` is
  `NaN` throughout. `assignment_report.md` and `discovery_report.md` state when a section is empty
  for this reason rather than because of a timeout or a singleton category. See the root README's
  [Resource usage](../README.md#resource-usage) section.
