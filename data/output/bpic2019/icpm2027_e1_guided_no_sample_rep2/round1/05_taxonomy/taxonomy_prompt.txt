You are subdividing a taxonomy axis that has already been declared by an organization's goal model. You have no authority to invent a different axis, merge unrelated alternatives together, or discard one of the declared alternatives — your task is only to set category boundaries *within* the axis the goal model already declares, using the narrative sample below to judge whether a declared alternative should be represented as one category or several (e.g. because the sample shows meaningfully different sub-patterns realizing it).

A *declared alternative* is a child of a goal-model element whose decomposition operator is OR or XOR: those are the points where the goal model declares that the process may proceed in one of several ways, and they are the axis you are subdividing. Children of an AND-decomposed element are not alternatives — they are steps that all contribute to the same parent, and none of them is a category on its own.

Every category you propose must be traceable to one or more goal-model element IDs (from the goal-task decomposition below) via its anchor_ids field. Default to one category per declared alternative — only depart from that default when the narrative sample gives you positive evidence to, under these rules:
- map 1:1 to a single declared alternative (using that alternative's own numeric id from the decomposition below (e.g. anchor_ids=["12"]) — never an invented label). This is the default; a declared alternative having few or no sampled narratives is not, by itself, a reason to fold it into another category. If that alternative itself decomposes further (its own children are AND-decomposed steps), anchor_ids still names only the alternative's own id — never also list its AND-decomposed descendant ids alongside it; those steps are not alternatives (line 3) and adding them does not make the anchor more precise, only redundant.
- subdivide one declared alternative into finer categories only if the sample shows it realized in meaningfully different ways — the category's rationale field must cite that evidence.
- combine several declared alternatives into one category only if both hold: (a) the goal model's own decomposition allows them to co-occur in one case (check the AND/OR/XOR operators shown in the decomposition — never combine alternatives the goal model marks XOR, i.e. mutually exclusive), and (b) the sample contains cases that actually realize them together, not merely that the goal model permits it. Cite that co-occurrence evidence in the category's rationale field.

Do not force every narrative in the sample into a category. Some narratives may not cleanly realize any declared alternative (e.g. still-open/pending cases, or unusual orderings) — that is expected and is handled by a later step, not by this taxonomy.

The goal model also declares what the organization *values* (softgoals, reached through contribution links) and how it *measures* whether a goal is met (indicators, with the value set converting a measurement to satisfaction). Use both: a category's rationale and description should say which softgoals its alternative advances or harms, and against which indicator its performance would be judged. They inform what a category *means*, never where its boundary falls — specifically:
- Two declared alternatives having similar or identical contribution profiles is not evidence to merge them. Only the co-occurrence rule above licenses a merge.
- An element that contributes to a softgoal but is not itself a declared alternative is still not a category. Contributing to something the organization values does not make a mandatory step an alternative to anything.
- An indicator is never a valid anchor_ids target. Anchor to the goal or task whose achievement the indicator measures, not to the measurement.

Activity labels in the narratives come from the event log and need not match goal-model element names verbatim: a logged activity realizes a goal-model element by meaning, not by string equality, and one goal-model element may be realized by several logged activities.
